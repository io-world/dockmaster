# Decisions

Format: date — decision — reason.

- **2026-10-01** — Single `pyproject.toml` at repo root (uv), code under `backend/`; dropped the `src/ndai` scaffold and build backend. — The app is run, not installed. Scripts add `backend/` to `sys.path`. One less moving part.
- **2026-10-01** — `.env` holds `ANTHROPIC_API_KEY` and is gitignored (it was not ignored in the initial scaffold). — Secrets never committed.
- **2026-10-01** — Minimum blank length depends on the source: drawn lines 40pt, typed underscores 18pt, drawn lines with text immediately beside them on the same row 12pt. — A single 40pt cutoff dropped real inline blanks like "the ____ day of ____, 20__". Underscores are always intentional, so a lower bar is safe. Short inline lines only count when text sits right next to them, which rules out decoration.
- **2026-10-01** — Lines that meet vertical rules at both ends are kept but flagged `in_table`, not dropped. — Table borders and real signature lines inside table cells look the same geometrically. Claude decides with the flag as a hint, which keeps recall high.
- **2026-10-01** — Label-only blanks: labels ending in a colon (`Date:`, `By:`, `Its:` …) always count. Bare labels (`Signature`, `Print Name`) count only when nothing else is within 60pt on their row. Letter-spaced text (`D a t e :`) is collapsed first. — Word exports often lose the signature lines and leave only the labels. These candidates are `label_offset`, so they always show as speculative in the UI.
- **2026-10-01** — Not handled: Word field-code text leaking into the text layer (e.g. `FORMCHECKBOX`) with no checkbox drawn. — No geometry to anchor to, and matching the literal string would be tuning to one document. The sender adds these by hand.
- **2026-10-01** — Lines with text covering more than 60% of their length are treated as underlined text and dropped. Below that, the text is kept as `existing_text`. — Separates underlined headings from blanks that are already partly filled.
- **2026-10-01** — Added field type `initials` (beyond signature/text/date/checkbox/radio). — Leases and many contracts have initials boxes on each page; showing them as "text" would ask the signer for the wrong thing.
- **2026-10-01** — Each field carries `filled_by: signer | sender`. — Many blanks (rent, effective date, party names in the preamble) are completed by the sender before sending. Without this flag, signers get asked to fill in terms of the deal.
- **2026-10-01** — The proposal includes `missing_fields`: places Claude expects a signature/initials/date but extraction found no blank. — These are shown as warnings, not invented boxes. Claude never outputs coordinates, so the sender places them manually.
- **2026-10-01** — Only pages that contain candidates are sent to Claude as images (110 dpi). All page text is sent. — Cuts image tokens on long documents. Text-only pages still give party context.
- **2026-10-01** — One Claude call per document, with no chunking yet. — An 18-page lease costs about 30k input tokens, which is far below limits. Chunking is deferred until a document needs it.
- **2026-10-01** — Model `claude-sonnet-5-5`, effort `medium`, server-side fallback on. Measured: NDA (4 pages) $0.047 / 12s; lease (18 pages) $0.10 / 22s. — The Haiku evaluation waits for score.py and labelled ground truth.
- **2026-10-01** — Code validates Claude's output: unknown IDs are dropped, unclassified candidates are added as unassigned with confidence 0, and signers without fields get a warning. Fields below 0.6 confidence or placed by `label_offset` get `needs_review`. — Errors stay visible instead of disappearing.
- **2026-10-01** — Headings are found per column (only text horizontally near the candidate), and Claude sees each candidate's x/y. — Side-by-side signature blocks (TENANT | LANDLORD) interleave in reading order. Before this fix, Claude assigned fields to the wrong column.
- **2026-10-01** — `backend/test_pdfs/*.pdf` is gitignored; only `*.labels.json` ground truth will be committed. — Some test documents are personal and must not be published.
- **2026-10-01** — Rotated pages: detection runs in the unrotated page space (where text is horizontal), and output bboxes are converted to display space with `page.rotation_matrix`. `rotation` is stored per page so stamping can convert back. — PyMuPDF returns text and drawings unrotated, but page size and renders are rotated, so boxes landed in the wrong place on /Rotate pages.
- **2026-10-01** — Raster line detection (OpenCV) also runs on pages with text whenever an image covers more than 50% of the page. — Scans that already have an OCR text layer have pixel lines, not vector ones; without this only typed underscores were found.
- **2026-10-01** — At most 20 page images are sent to Claude: the pages with the most candidates, plus the last page. Text for all pages is always sent. — The API limit is 100 images per request, and cost scales with images.
- **2026-10-01** — The Claude call streams with `max_tokens=64000`, and a `max_tokens` stop is reported as its own error. — At 16k, thinking plus a large form could exhaust the limit and lose the whole proposal.
- **2026-10-01** — Password-protected, empty or non-PDF uploads raise a clear `ValueError` message. — A crash with a stack trace is not something a user can act on.
- **2026-10-01** — No OCR engine. Scanned pages are handled by Claude's vision: every page image sent to Claude has each candidate drawn as a red box labelled with its ID, scanned pages are always sent (within the 20-image cap) and rendered at 150 dpi, and the prompt says to read labels from the image. PyMuPDF's Tesseract hook is still tried in case Tesseract is present. — Tesseract can't be installed via uv (it's a system program). RapidOCR would add about 50 MB, and PaddleOCR about 300 MB plus a NumPy <2.4 conflict. Claude already receives the images. Tested on a fully rasterised NDA (zero text): both signature blocks were assigned correctly at 0.95 confidence. The labelled boxes also help digital PDFs with side-by-side columns.
- **2026-10-01** — Known gap on scans: label-only blanks ("Date:" with no line) can't be detected, and short inline lines under 40pt (e.g. "State: ____") are dropped, because both rules need extracted text. Claude flags these as missing or in warnings, and the sender adds them by hand.
- **2026-10-01** — Added `score.py` with hand-corrected labels for the 4 test PDFs (`backend/test_pdfs/*.labels.json`, not yet verified by the user). Labels are keyed by page + bbox, not candidate ID, so they survive changes to extraction. Genuinely ambiguous ownership (notice addresses, single-party execution dates) is marked `owner_any`.
- **2026-10-01** — Kept `claude-sonnet-5-5` over `claude-haiku-4-5`. Measured on the 4 labelled PDFs (69 fields): Sonnet 94% end-to-end, $0.23, and every high-confidence field correct; Haiku 77% end-to-end, $0.10, with 13 wrong fields at ≥0.8 confidence (mostly the lease's signer columns). Unearned confidence is exactly what the "handles being wrong" criterion penalises, so the saving of about $0.03 per document isn't worth it.
- **2026-10-02** — Backend built before the frontend, with the frontend spec as the guide (the API didn't exist yet). All routes are under `/api` so they can't clash with frontend routes. In production, FastAPI serves `frontend/dist` with an `index.html` fallback.
- **2026-10-02** — Auth: email + password (PBKDF2 from the standard library) with a server-side session in an httpOnly cookie. Signers need no account: their link token is the credential, and pages and the final PDF are served under `/api/sign/{token}/…`. — It's the simplest option that works on one origin. Hardening is out of scope.

The sender types the values, Send is blocked until the required ones are filled, and the values are stamped into the final PDF and shown read-only to signers. — Otherwise rent and party names would land in Needs review or be pushed onto signers.

- **2026-10-02** — Signing order: signers in the lowest unsigned `order` group are notified together, and the next group is notified once that group finishes. The AI defaults everyone to order 1, so everyone signs in parallel. — This supports sequencing without extra UI.

- **2026-10-02** — Stamping inserts content unrotated in the page's own coordinate space, so on /Rotate pages it runs in the same direction as the document's text. Verified on a 90° page with transparent-PNG signatures.

Signing: drawn round controls (native radios have a fixed size and margin and missed small markers), one pick per choice, and each required choice counts once in "fields left". Backend: `save_draft` requires a group on radios only; `send` blocks a choice with mixed owners; submit rejects two picks in one choice and requires one for a required choice. Stamp: a filled dot in the stamp colour (the original widget's own state isn't changed, as with checkboxes). `field.group_id` is a new column, added to existing databases by a small `ALTER TABLE` check in `db.init_db` (tested on a copy of the dev database). The 7 real test PDFs gain no radio candidates. — Forms with "choose one" options were shown as checkboxes, or not detected at all.
